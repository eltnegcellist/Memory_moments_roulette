# E2E監査の途中結果

対象 main: `23d15e81089b23939d6215f5a9c7bc6ae2a84e5b`（PR #52 のGIFスタンプ修正を含む）。Mac上、隔離されたPlaywright Chromiumコンテキスト、ローカルHTTP。入力はCanvasで生成した色と番号付きの合成画像。OS保存ピッカーを無効化してブラウザのダウンロードを検査。Service Workerはブロック。外部共有は行っていない。

## 実行済みの範囲

- Desktop Chromium: 受信・共有・破損入力・ディープリンク4テスト、GIF1テストが成功。選択写真のマスクON/OFFは明示的に2コマ目を選んだ手順で3/3成功。
- Mobile Chromium（Pixel 7相当）: 6テスト成功。実機ではない。
- WebKit: 主要5テスト成功。
- 履歴から合成ルーレットAを選択し、共有後に対象選択へ戻る経路と画像を確認。
- GIF: 旧履歴形式で合成8画像をseed。GIF画面からスタンプエディタを開いてGIF画面を維持、GIF89aの8フレームと0.2秒の遅延、および先頭フレームのスタンプ位置の画素差を確認。通常GIFの5段階の生成ファイルの遅延を確認。全フレームの内容・順序とプレビューの実時間は未検査。
- 受信した合成2画像はplay→share→play→receiveの戻り経路を通り、DB各ストアの件数は変化しなかった。件数以外の内容の完全比較は未実施。
- 遊べる共有ファイルのJSON形式と画像配列、選択写真のJPEGの識別色とマスクON/OFFの画素差を確認。
- 破損JSONは受信画面でエラー、DB各ストア件数は不変。
- 空データの探索: seed 1〜10、それぞれ100往復（200操作）でホームと7画面の遷移を実行。URL、表示ルート、pageerrorを検査。空状態の限定的な探索であり全遷移辺の網羅ではない。

発見した確定不具合: 今回実行した限定範囲ではなし。初期テストで停止コマを1と誤認した失敗は、明示選択後に3回成功し、アプリ不具合として数えない。初回のDB件数差も非同期初期化前後を比較していたテストの問題であり、初期化待ち後の再実行では不変。

CI初回は15件中14件成功、1件失敗。自動回転中のコマを固定と仮定したテスト側の競合を修正し再検証中。PWA/SW、通常動画取り込み、Galaxy S25、Android共有シート、LINE互換性は未検証。未テストの大部分があるため、重大不具合がないとは結論できない。
