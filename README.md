# 思い出ルーレットおみくじ

**現在の公開バージョン：v1.3.0**（共有スタジオ追加）

**自分では選ばなかった一枚に、偶然出会う。**

写真を撮るとき、私たちは笑顔やきれいに写った「いい瞬間」を残そうとします。  
でも動画には、その間の半目や動きの途中、思いがけない表情まで、たくさんの一瞬が残っています。

普通なら写真にしなかった一瞬を、ルーレットで偶然引く。  
「こんな顔してたんだ」「こんな一瞬あったんだ」と、家族や身近な人と楽しむ。  
そして、その偶然の一枚におみくじを重ねて、今日だけの結果として楽しむ。

**よく撮れた一枚を探すのではなく、自分では選ばなかった一枚に出会う。**

それが、このアプリの中心にある体験です。

## v1.3 — 共有スタジオ

通常ルーレットでSTART・STOPした結果を短い無音動画として再構成して保存できます。動画出力は対応ブラウザでMP4、それ以外ではWebMです。動画を手動で保存し、対応端末ではAndroid等の共有メニューからLINEなどを選択できます。MP4/LINEの組み合わせは実機で確認が必要です。

「相手も遊べるルーレットを作る」は、元動画ではなく抽出した複数コマを含む .mmrplay を作成します。受け取った人はWebサイトの「共有・受け取る」からファイルを選ぶと、ブラウザ上でそのルーレットを回せます。専用サーバー・会員登録・PWAインストールは不要です。受信したルーレットは既存デッキや履歴に自動保存しません。

「ひみつスタンプ」は手動で各画像の隠す位置を指定して、PNG/JPEG相当の写真・GIF・共有用ルーレット・通常抽選動画を作れます。動く顔の自動追従はまだありません。**顔を覆ってもほかの人物・背景・文字などから個人が特定される可能性があります。必ず全コマを確認してください。**

Web Share APIで共有先を選んだ場合のみ、LINEなどに画像が渡ります。アプリ側のサーバーへ画像の自動アップロードはしません。共有先のアプリ・クラウドにはそのサービス独自の保存・転送ルールが適用されます。

**今回はPWAの共有受信（Web Share Target）を追加していません。** Galaxy S25とLINEでの送信・受信・動画再生は未検証です。

## v1.1 — 思い出おみくじデッキ

v1.1では、1本の動画ごとに遊ぶだけでなく、**複数の思い出動画から抽出した一瞬を端末内にためて、いつでも引ける「思い出おみくじデッキ」**を追加しました。

### 基本の流れ

1. 「思い出動画を追加する」から、1本または複数の動画を選ぶ
2. 各動画から8〜15個程度の一瞬を自動抽出
3. 抽出した一瞬を端末内のデッキに保存
4. 保存済み動画をサムネイル一覧から選ぶ
5. 選んだ動画だけで「おみくじを引く」
6. 新しい動画を撮ったら、あとからデッキへ追加

長い動画だけが候補を占有しないよう、1本あたりの抽出数には上限を設けています。

### 同じ結果を繰り返しにくい抽選

デッキでは**シャッフルバッグ方式**を採用しています。

原則として、デッキ内の候補を一巡するまでは同じ一瞬を結果として再び出しません。一巡すると再シャッフルします。

### 運勢と写真は別々

v1.1では、写真の特徴と運勢を切り離しました。

笑顔だから大吉、半目だから凶、といった判定はしません。  
止まった一瞬とは独立して、その場で運勢を抽選します。

**写真の出来を運勢で評価するものではありません。**

## このアプリが目指すこと

### 自分では選ばなかった一枚に出会う

写真では、笑顔やきれいに写った姿など、「残したい瞬間」を自分で選びます。  
一方、動画には、その前後や途中の一瞬まで残っています。

- 半目になった顔
- 動きの途中
- ちょっと変なポーズ
- 思いがけない表情
- 本人も気づいていなかったような一面

このアプリは、それらを「失敗写真」として扱うのではありません。  
また、変な写真や笑える写真を高く評価するものでもありません。

**普通なら自分では選ばなかった一瞬に、偶然出会うことそのものを楽しみます。**

そこで生まれる「こんな顔してたんだ」「こんな一瞬あったんだ」という発見を、家族や身近な人との会話や笑いにつなげることを目指しています。

### おみくじは、偶然をもう一段楽しむための仕掛け

まず、どの動画のどの一瞬で止まるか分からない。  
さらに、止まった一枚とは独立して、その場で運勢も決まる。

**自分では選ばなかった一枚との偶然の出会いに、もう一つの偶然を重ねる。**

それが「思い出ルーレットおみくじ」です。

### もともとは育児動画から始まりました

赤ちゃんの動画をコマ送りすると、写真としては残していなかったさまざまな表情が見つかることから始まったアイデアです。

現在は、赤ちゃんや子どもの成長記録だけでなく、家族、友人、ペット、旅行、結婚式、イベントなど、さまざまな思い出動画で使える形に広げています。

## 動画から一瞬をどう選ぶ？

候補抽出では、

- 何も判別できないほど破綻したフレームを避ける
- 真っ黒・真っ白に近いフレームを避ける
- ほぼ同一のコマが大量に並ぶのを減らす
- 動画内の一部分だけに偏りすぎないようにする
- 見た目の違う一瞬を幅広く残す

といった処理を行います。

一方で、

- 半目
- 変顔
- 動きの途中
- 少しのブレ
- 横向き
- 何気ない場面

だからという理由では除外しません。

### 特徴度

LAB設定では「特徴度」を表示できます。

これは写真の品質点ではありません。  
「くっきり」「珍しさ」「前後からの変化」などを、候補同士の違いを見るための補助情報として表示するものです。

運勢の決定には使用しません。

## デッキ管理

保存済み動画は、ファイル名だけの一覧ではなく**動画サムネイルのライブラリ**として表示します。

- ブラウザから取得できる動画ファイルの日付をもとに月ごとにグループ表示
- サムネイルをタップして今回使う動画を複数選択
- 動画名検索
- 新しい順 / 古い順
- 「すべて選択」「選択解除」
- 選択状態を端末内に保存
- 追加済み動画の本数
- 保存している一瞬の数
- 使用容量
- 動画単位の削除
- デッキ全体の削除
- バックアップ
- 復元

新しく追加した動画には長辺320px程度の小さな専用サムネイルを保存します。既存のv1.1デッキについても、最初の候補画像からサムネイルを自動生成するため、元動画を選び直す必要はありません。大量デッキでは画面に近いサムネイルだけを遅延生成・読み込みし、おみくじ開始時も選択した元動画の候補だけをIndexedDBから読み込みます。

写真を1枚ずつ整理する写真管理アプリにはせず、**スマートフォンの写真アプリに近い見た目で、元動画単位を選ぶ**ためのライブラリにしています。

### 重複動画

ファイル名、ファイルサイズ、更新日時、動画時間から動画を識別し、同じ動画の二重追加をできるだけ防ぎます。

## 保存容量

候補画像は元動画そのものではなく、ルーレット用の静止画として保存します。選抜後の一瞬だけを長辺最大1280pxで再取得し、対応ブラウザではWebP、非対応時はJPEGで保存します。

現在の目安：

- 1動画：8〜15個
- 通常の保存画像：長辺最大1280px
- 特別リプレイ：長辺420px・12コマ・WebP品質0.70（非対応時JPEG）
- 通常候補：停止位置の約3秒前 → 停止位置
- 冒頭2.5秒未満：停止位置 → 約3秒後を保存し、逆向きに再生
- 最大：1,500個の一瞬
- アプリ側のデッキ上限：約650MB
- 実際にはブラウザの利用可能容量が少ない場合、そちらを優先して保存を停止

利用可能な環境ではブラウザのストレージ使用量も確認します。

---

## ルーレット履歴の保存方式

v1.1のデッキから作ったルーレット履歴は、候補画像そのものを履歴ごとに複製せず、**deckFramesの候補IDを参照して保存**します。履歴を開くときだけ必要な画像を読み込みます。

これにより、同じ候補画像がルーレット履歴の数だけ重複してIndexedDBを消費する問題を避けます。旧v1.0形式の独立ルーレットは互換性のため画像込みのまま維持します。

デッキの元動画データを削除した場合、そのデータを参照している新形式の履歴は再生できなくなります。履歴自体は一覧から削除できます。

---

## 動画ライブラリの日付

過去動画一覧の日付は、**アプリへ追加した日時ではなく、ブラウザが動画ファイルから取得できる `lastModified` を優先**します。取得できない場合のみ追加日時を使います。

Webブラウザでは動画コンテナ内の本来の撮影日時を必ず取得できるわけではないため、スマホの純正フォトアプリと完全に同じ撮影日時になるとは限りません。

---

## 保存の耐久性とバックアップ

デッキはIndexedDBに保存します。

利用可能な環境では `navigator.storage.persist()` を使って永続保存を要求しますが、ブラウザデータは端末・ブラウザの操作や保存領域の状況によって消える可能性があります。

そのため、

- 継続利用する場合はホーム画面へ追加
- 大切なデッキは「デッキを書き出す」でバックアップ

を推奨します。

バックアップには候補画像・特別リプレイ・メタデータを含め、**元動画そのものは含めません。**

新しいバックアップは `.mmrbackup` 形式で、レコードを順次書き出します。対応ブラウザではファイルへ直接、Androidなどでは可能な限りOPFSの一時ファイルを経由して生成し、数百MB級でも巨大なJSON文字列を一度にメモリへ作らない設計です。従来のJSONバックアップも復元できます。

---

## 複数動画の処理

複数動画を選んだ場合は1本ずつ処理し、1本終わるごとにデッキへ保存します。

処理中にタブをバックグラウンドへ移した場合は処理を一時停止し、戻ったときに続きから再開します。

シーン分析や高画質画像・特別リプレイの仕上げ中は、対応ブラウザでは元動画を一時的にOPFSへ退避します。コピーが完了していれば、ブラウザやページが終了しても次回起動時に未完了処理を自動再開します。ブラウザがOPFSに対応していない場合や、一時保存が完了する前に終了した場合だけ、同じ動画の再選択が必要になることがあります。仕上げが完了した元動画の一時ファイルは自動削除します。

## 主な機能

### 🎴 おみくじモード

思い出デッキまたは従来の保存ルーレットから一瞬を引き、STOP時に運勢を独立抽選します。

### 🎯 通常ルーレット

運勢を付けず、どの一瞬で止まるかだけを楽しめます。

### 🎊 特大吉 / 🌈 大逆転大吉

低い確率で特別な運勢とリプレイが発生します。

大凶以外では、従来の特別演出が発生した回を通常運勢とは別の写真賞にせず、特別運勢「特大吉」として扱います。写真の良し悪しを評価するものではなく、その場で偶然出会った一瞬まで含めて、その回のおみくじ結果です。

大凶では一定確率で「大逆転大吉」になります。

元動画を利用できる場合は従来どおり元動画からスローリプレイします。デッキへ保存した候補には、長辺420px・12コマの低解像度リプレイを別領域に保存するため、後日元動画を選び直さなくてもスローリプレイできます。通常は停止位置より前の約3秒、動画冒頭の候補だけは停止位置より後ろの約3秒を保存して逆向きに再生します。

### 🖼 お気に入り

結果の中から「残しておきたい」と思った一瞬をアプリ内に保存できます。

### 🎞 動画からGIFを作る（ルーレットとは独立）

ホーム下部の小さな「GIF作成」から専用画面を開きます。ルーレット作成と同様、最初に **「新しい動画から作る」「過去の動画から作る」** を選択します。

「新しい動画」では端末の動画を選び、抽出コマを保存してルーレットを起動せずGIF編集へ進みます。「過去の動画」ではルーレット用ライブラリと同じ、日付グループ・検索・新しい順／古い順の小さな3列サムネイルから動画を選択します。GIF作成は一度に1本です。選択後だけ3コマの見本と切り替え速度、作成ボタンを表示します。

**従来のデッキ動画だけでなく、以前のルーレット履歴（旧creations形式）の保存画像にも対応**しています。旧形式の元動画ファイルがなくても保存画像が2枚以上あればGIFを作れます。ただし画像自体が消去された動画からは復元できません。過去の複数動画が混在したルーレットは、保存された元動画IDごとに分離し、異なる動画のコマを混ぜません。

GIF用とルーレット用の動画素材は同じ端末内デッキ（deckSources・deckFrames）に保存します。同じ動画を両方の機能で取り込んでも、動画の特徴に基づいて重複判定して既存素材を再利用します。GIFから新規取り込みしてもルーレットの動画選択状態（selectedSourceIds）や作成履歴（creations）は変更しません。ルーレット側に素材が加わるため「過去の動画から作る」で使用できます。GIFファイルは利用者が保存する方式で、アプリ内のルーレット作成履歴には登録しません。

GIFは元動画の全フレームではなく保存済みの抽出コマを元動画内の時刻順に並べます。プレビューと保存GIFの切り替え間隔は0.05・0.1・**0.2秒（初期値）**・0.5・1秒を選べます。

## プライバシー

個人的な思い出動画を扱うため、**動画や写真を解析用サーバーへ送らないこと**を重要な設計条件にしています。

動画のフレーム抽出、候補比較、デッキ保存、運勢抽選、GIF生成、「お気に入り」の保存などはブラウザ内で行います。

元動画を解析用サーバーへアップロードするAPIはありません。

## 既存v1.0データ

v1.0までに保存したルーレットや「お気に入り」は削除せず、そのまま残します。

v1.1の思い出デッキは新しい保存領域を追加して実装しています。

## 設定

ホームの「設定」に、ルーレット作成に関する設定とデータ管理をまとめています。

### ルーレット設定

- **抽出枚数**：おまかせ（8〜15枚） / 8枚 / 12枚 / 15枚
- **通常ルーレットにする**：運勢なしで「どの一瞬に止まるか」だけを楽しむ
- **運勢サンプルを表示する**：候補確認用の運勢サンプルを表示

これらは新しい動画から作る場合も、過去の動画から作る場合も共通です。設定値は端末内に保存され、次回以降にも引き継がれます。

作成画面には設定項目を置かず、動画選択と処理状況だけに集中できる構成にしています。
