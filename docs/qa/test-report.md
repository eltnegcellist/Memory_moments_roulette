## 発見した不具合: GIF動画名検索が一致しない（Medium）

対象: S02、Desktop Chromiumで4/4回、モバイル相当Chromiumで1/1回再現。Mac WebKitでは実合成WebM取り込み後と合成DB素材で再現（Linux CI WebKitの動画取込は未確認）。main `23d15e8`。合成動画A/BをGIF画面の入力から取り込む。保存された `deckSources.fileName` が `synthetic-a.webm` と `synthetic-b.webm` であることを確認。「別の動画を選ぶ」から検索欄へ `synthetic-a` を入力すると、期待するAのカードが表示されず、検索該当なしになる。画面は「日付・動画名で検索」と案内している。自動再現: `npx playwright test --project=desktop-chromium tests/e2e/gif.spec.ts --grep 'S02/S19'`。失敗時のtraceとスクリーンショットが生成される。

原因候補: `deck.js` のGIF用カタログ `__memoryGifListSources` は日付ラベルを渡すが `fileName` を渡さず、`features.js` の `renderGifSourceCards` はその日付ラベル等のみを検索する。通常ライブラリの `sourceSearchText` はファイル名を含む。最小修正案: GIFカタログに検索用ファイル名を含め、GIFのフィルターでも検索対象にする。旧履歴は従来のタイトルを維持し、日付検索・大小文字・選択状態を回帰確認する。アプリ本体は未修正。

## 発見した不具合: GIF取込時の容量不足が形式エラーのように案内される（Medium）

対象: S18、Desktop Chromium、main `23d15e8`、2/2回再現。合成の既存履歴を用意し、GIF動画取り込み中の `deckSources` 書込を `QuotaExceededError` とするようテスト環境で模擬した。履歴レコードは不変だったが、GIF画面は「新しく取り込める動画がありませんでした。保存済みの動画を選ぶか形式を確認してください。」と表示し、容量不足を説明しない。実端末で容量を使い切った試験ではない。自動再現: `npx playwright test --project=desktop-chromium tests/e2e/receive.spec.ts --grep "quota failure during video"`。

原因候補: `deck.js` は取り込み例外を個別に捕捉してエラーを別画面の通知に記録し、空のID配列を返す。`features.js` のGIF入口は空配列を形式等の問題として一律に扱う。最小修正案: 取り込み結果にエラー種類を含め、容量不足をGIF画面上に明示し、既存データを保持した再試行経路を確認する。アプリ本体は未修正。
